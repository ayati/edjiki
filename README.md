# edjiki

自動タイムスタンプ降順テキストエディタ。PC / Android Chrome で動作する単一 HTML アプリです。

- 新規エントリを先頭に挿入し、常に降順（新しい順）で管理
- ローカルは `localStorage` に自動保存（debounce 300ms）
- `.txt` のダウンロード / インポート（UTF-8 / Shift-JIS を自動判別、出力は UTF-8 固定）
- Google Drive への自動保存・読込（マージ方式）
- public / private フラグ
- **private エントリのパスワード保護**（AES-GCM 256bit 暗号化）
- **編集の簡易 undo**（最大 20 ステップ・合計 5 MiB まで）
- **全画面編集モード**（集中執筆向け。PC はホバーで ⛶、スマホはメニューから。全画面終了時に Drive へ自動保存）
- **集中執筆モード FAB**（⚙ 設定で ON にすると右下ボタンが ✏ になり、新規作成と同時に全画面へ）
- **Drive 自動保存**（100文字入力ごと・入力停止10秒後・アプリ切替時・画面復帰時・オンライン復帰時・全画面終了時に自動で Drive へ保存）
- **起動時 Drive 同期**（ページを開いて「☁ Drive 接続」をタップすると認証＆最新を自動取り込み。他端末で書いた内容を意識せず反映）
- **年別アーカイブ**（Drive 専用フォルダに `jkYYYY.txt` / `.zip` を保存し、古いエントリをローカルから切り捨て）
- 配色テーマのプリセット（7種類）
- フォントサイズ・行間・書体を自由にカスタマイズ（太字・疑似ボールド 4 段階・ライブプレビュー付き）
- カスタムフォント（インストール済みフォントの名前指定 / フォントファイルの取り込み）
- **ファイル形式設定**（改行コード: LF / CRLF、日付フォーマット: `YYYY/MM/DD` / `YYYY-MM-DD` / ISO 8601 拡張形式）

## クイックスタート（ローカル確認）

`file://` で直接開くと Google OAuth が動作しないため、必ず HTTP 経由で起動してください。

```bash
cd edjiki
python3 -m http.server 8080
```

ブラウザで `http://localhost:8080/edjiki.html` を開きます。

Google Drive 連携が不要であれば、`config.js` がなくてもエディタとしてすぐ使えます。

## 基本的な使い方

### エントリの作成

次のいずれかの方法で新規エントリを先頭に追加できます。

- ヘッダ右上の **＋新規** ボタン（常に通常モードで追加）
- 画面右下の **＋** ボタン（FAB）
- キーボードショートカット `Ctrl+D` / `Ctrl+N` / `Ctrl+M`

テキストエリアに本文を入力すると、300ms のデバウンスで自動保存されます。

> **集中執筆モード（スマホ向け）**: ⚙ 設定の「新規作成（✏ ボタン）を集中執筆モードで開く」を ON にすると、FAB が **✏** に変わります。✏ をタップすると新規エントリの作成と同時に全画面モードへ入り、すぐに書き始められます。前のエントリを参照しながら書きたいときはヘッダの **＋新規** を使います。

### エントリの編集

| 操作 | 方法 |
|---|---|
| 本文編集 | テキストエリアを直接クリックして入力 |
| タイムスタンプ変更 | エントリ上部の日時表示をクリック → 秒単位まで編集可能 |
| public / private 切替 | エントリ上部の **🔓 public** / **🔒 private** ボタン、または `Ctrl+P`（パスワード設定時のみ有効） |
| 削除 | エントリ上部の **✕** ボタン（確認ダイアログなし。全画面モード中は非表示） |
| 全画面モード | マウス: エントリにカーソルを乗せると右上に ⛶ が現れる。スマホ・PC共通: ⋯ メニュー →「全画面モードへ」または `Ctrl+Enter`。終了は **✕ 閉じる** または `Esc`。全画面終了時に Drive への自動保存が実行される（Drive 認証済み・自動保存 ON 時） |

テキストエリアからフォーカスが外れると、空行の削除・末尾空白の除去が自動で行われます。本文が空になったエントリは自動削除されます。

### 元に戻す（Undo）

直近 20 ステップまで操作を取り消せます（合計 5 MiB を超えると古いものから順に破棄）。

| 操作 | 方法 |
|---|---|
| 1 ステップ戻る | `Ctrl+Z`（テキスト入力中は無効） |
| メニューから選ぶ | **⋯** → **↩ 元に戻す (N)** |

スナップショットが取得されるタイミング：
- テキストエリアにフォーカスしたとき（編集開始前）
- 編集中に **200 文字** 以上の差分が累積したとき、または前回 push から **30 秒** 経過した直後の入力時（IME 変換中はスキップ）
- **✕** 削除ボタンを押す直前
- タイムスタンプ変更・全画面終了時の空エントリ自動削除・ファイルインポート・Drive 競合マージ／読込マージ・アーカイブ実行の直前

次のタイミングで undo スタックは **クリア** されます：
- パスワードによるロック実行時
- パスワードの設定変更・削除時
- Drive ログアウト時

> テキストエリア内での `Ctrl+Z` はブラウザ標準のテキスト編集 undo として動作します。フォーカスをエリア外に移してから押すとアプリ全体の undo になります。

### パスワード保護

設定パネル（**⚙**）からパスワードを設定できます。設定後は private エントリが **AES-GCM 256bit** で暗号化されて `localStorage` に保存されます。

| 操作 | 方法 |
|---|---|
| パスワード設定 | ⚙ →「🔐 パスワードを設定...」|
| 解除（セッション中） | ヘッダの **🔐** ボタン → パスワード入力 |
| ロック | ヘッダの **🔓** ボタン |
| パスワード変更 / 削除 | ⚙ →「🔑 パスワードを変更...」/「🔓 パスワードを削除...」|

- **パスワード未設定時は private への切替ができません。** 暗号化するには先に⚙でパスワードを設定してください。
- **パスワードを忘れると private エントリは復元できません。** 定期的に Drive へ保存してください（Drive の `.txt` は平文で保存されます）。
- ロック中の private エントリは検索・編集・エクスポートできません。削除は可能です。
- ページをリロードすると自動的にロックされます。
- `.txt` ダウンロード時に private エントリが含まれる場合は警告が表示されます（出力は常に平文です）。

### 検索

ヘッダの **🔍** ボタン、または `Ctrl+F` で検索バーを開きます。

- 本文の部分一致検索
- `YYYY/MM/DD` または `YYYY-MM-DD` の前方一致検索（例: `2026/04` や `2026-04` と入力するとその月のエントリだけ表示）

`Esc` キーまたは **✕** ボタンで検索バーを閉じます。

### アーカイブ検索

アーカイブフォルダ（Drive 設定済みの場合）と Google Drive が設定されていると、検索バーの下に **「📦 アーカイブも検索」** ボタンが表示されます。

クリックすると Drive 認証後にアーカイブフォルダ内の `jkYYYY.txt` を検索し、現行データとは別に結果を表示します。

| 操作 | 説明 |
|---|---|
| **「📦 アーカイブも検索」** をクリック | Drive に保存済みの全アーカイブファイルを対象に検索 |
| 検索クエリを変更 | 結果をリセット（再度ボタンで検索） |
| **「📦 再検索」** をクリック | 同じクエリで再実行 |
| 結果カードの **「インポート」** をクリック | そのエントリを現行データに取り込む（`mergeEntries` によるマージ） |

- 一度ダウンロードしたファイルはセッション中キャッシュされるため、クエリを変えても再ダウンロードは発生しません
- アーカイブ内の private エントリも検索対象です（アーカイブファイルは平文保存のため）
- アーカイブ実行後はキャッシュが自動的に無効化されます

## テキストファイル形式

ダウンロード・インポート・アーカイブで使用するテキストファイルの形式です。⚙ →「日付フォーマット」で 3 種類の形式から出力形式を選択できます。**読込時はいずれの形式も自動認識される**ため、形式を変更しても既存ファイルは引き続きインポートできます。

### 3 つのフォーマット

#### 1. `slash`（標準・デフォルト）

```
2026/04/13 21:43:10 公開エントリの本文
複数行の本文も可
2026/04/13 -20:15:00 非公開エントリの本文（秒の前にハイフン）
```

#### 2. `dash`

```
2026-04-13 21:43:10 公開エントリの本文
2026-04-13 -20:15:00 非公開エントリの本文
```

スラッシュの代わりにハイフンを日付区切りに使う形式。日時の途中はスペース区切りのまま。

#### 3. `iso`（ISO 8601 拡張形式）

```
2026-04-13T21:43:10+09:00 公開エントリの本文
2026-04-13T21:43:10+09:00* 非公開エントリの本文（オフセット直後にアスタリスク）
2026-04-13T12:43:10Z UTC で記録した公開エントリ
2026-04-13T12:43:10Z* UTC で記録した非公開エントリ
```

日付と時刻の区切りに `T` を使い、末尾にタイムゾーンオフセット（`+09:00`、`-05:30` 等）または `Z`（UTC）が付く ISO 8601 / RFC 3339 互換形式。**公開エントリのみで完結する場合は strict ISO 8601 に準拠**します。

### private エントリのエンコード方法

| フォーマット | 公開エントリ | 非公開エントリ |
|---|---|---|
| `slash` | `2026/04/13 21:43:10 body` | `2026/04/13 -21:43:10 body`（時刻部の先頭に `-`） |
| `dash`  | `2026-04-13 21:43:10 body` | `2026-04-13 -21:43:10 body`（時刻部の先頭に `-`） |
| `iso`   | `2026-04-13T21:43:10+09:00 body` | `2026-04-13T21:43:10+09:00* body`（オフセット末尾に `*`） |

#### ISO 8601 における `*` 拡張について

ISO 8601 では時刻部の先頭に `-` を置けません（タイムゾーン符号と衝突するため）。そこで edjiki では **「タイムスタンプトークンの末尾にアスタリスク `*` を接着する」** という独自の拡張を採用しています。

- **公開行はそのまま strict ISO 8601** — `2026-04-13T21:43:10+09:00 body` は他のツールでもパース可能です。
- **非公開行は `*` 1 文字を剥がせば strict ISO 8601** — `2026-04-13T21:43:10+09:00* body` は edjiki 独自の拡張ですが、`*` を取り除けば標準のタイムスタンプとして扱えます。
- 設計思想は既存の `-21:43:10` 規約と同じく「タイムスタンプトークンに修飾子を付ける」というもので、本文側の文字種を一切制約しません（本文先頭が `*`, `-`, `#` でも問題ありません）。

> 「private エントリを使わない／private を切り出して別ファイル管理する」運用なら、edjiki の出力ファイルは strict ISO 8601 として他のツールから扱えます。private を含む場合は edjiki 自身またはその仕様に従う他のパーサで読み込んでください。

### タイムゾーンオフセットの扱い（ISO 8601 形式のみ）

ISO 8601 形式を選んだ場合、⚙ →「タイムゾーン」で 3 つのモードから選択できます。

| モード | 動作 | 用途 |
|---|---|---|
| **自動（保存時のオフセットを保持）** | エントリごとに記録されているローカルオフセットをそのまま出力。書いた時刻の真の状況を保持できる（**デフォルト**） | 海外移動・引っ越しで TZ が変わる人、書いた瞬間の状況を残したい人 |
| **UTC（Z）** | すべてのエントリを UTC に変換し `Z` 表記で出力（例: JST 21:43 → UTC 12:43Z） | TZ に依存しない正規化形式で長期保存したい人 |
| **固定オフセット** | 指定したオフセット（`-12:00`〜`+14:00` の 30 分刻み）に変換して出力。「現在のローカル」ボタンでブラウザの現在の TZ に一括設定可能 | 常に同じ TZ で書きたい人、特定の TZ にロックしたい人 |

なお、内部表現（`localStorage` 上の `state.entries[].time`）は常に「書いた時のローカルオフセット込み ISO 8601」のまま変わりません。出力形式の切り替えは serialize 層のみに影響します。

### 共通ルール

- 行頭がヘッダ条件にマッチする行がエントリの開始。それ以降の行が本文。
- 空行は禁止（インポート時に無視されます）。
- 出力時は `serializeTxt` が現在の `dateFormat` 設定にしたがって 1 形式で書き出しますが、**入力時は 3 形式すべてを自動判別**します。3 形式を混在させたファイルもパース可能です。
- インポートした ISO 形式の `Z` は内部表現で `+00:00` に正規化されます（重複検出シグネチャの安定化のため）。

### 文字コードと改行コード

| 設定 | 出力（ダウンロード・Drive 保存） | 読込（インポート・Drive 読込） |
|---|---|---|
| 文字コード | UTF-8 固定 | UTF-8 / Shift-JIS を自動判別（BOM 付き UTF-8 にも対応） |
| 改行コード | LF または CRLF（⚙ で選択） | LF / CRLF どちらも自動対応 |
| 日付フォーマット | `slash` / `dash` / `iso` から選択（⚙） | 3 形式すべてを自動認識 |

アーカイブファイル（`jk2025.txt` など）も同じ形式のため、**⋯ → ファイルから読込** でそのままインポートできます。アーカイブも現在の `dateFormat` 設定で書き出されます。

## 表示のカスタマイズ（設定パネル）

ヘッダの **⚙** ボタンで設定パネルを開きます。設定は `localStorage` に保存され、次回起動時に復元されます。

### 配色テーマ

7種類のプリセットから選択できます。各テーマは色見本（背景色＋アクセント色）付きで表示されます。

| テーマ | 特徴 |
|---|---|
| 自動 | OS のダーク / ライト設定に追従（デフォルト） |
| ダーク | VS Code 風の落ち着いたダーク |
| ライト | シンプルな白ベース |
| セピア | 和紙・古書のような暖色系。長時間の読み書きに |
| さくら | 桜の淡いピンク |
| ブルー | 深海・夜の水面を思わせるダークブルー |
| ノルド | 北欧の冬をイメージした人気の Nord パレット |

### フォントサイズ

スライダーで 12px〜24px の範囲を 1px 刻みで調整できます（デフォルト: 16px）。

### 行間

スライダーで 1.2〜2.0 の範囲を 0.1 刻みで調整できます（デフォルト: 1.6）。

### フォント

書体名はそれぞれの書体でプレビュー表示されます。

| カテゴリ | フォント名 | 特徴 |
|---|---|---|
| ゴシック | BIZ UDPGothic | UD 書体。読みやすさ重視（デフォルト） |
| ゴシック | M PLUS 1p | すっきりとした現代的なゴシック |
| ゴシック | M PLUS Rounded 1c | 丸みのある柔らかなゴシック |
| ゴシック | Noto Sans JP | Google の標準的な和文サンセリフ |
| 明朝 | Noto Serif JP | Google の標準的な和文明朝 |
| 明朝 | ZEN オールド明朝 | 伝統的な活字の雰囲気 |
| 明朝 | しっぽり明朝 | 活字らしい本格的な明朝体 |
| 明朝 | さわらび明朝 | 細くすっきりした明朝体 |
| 明朝 | ひな明朝 | やや手書き風の明朝体 |
| 汎用 | 汎用セリフ | OS 標準のセリフ体（Windows: 游明朝など） |
| 汎用 | 汎用サンセリフ | OS 標準のサンセリフ体 |
| 等幅 | ui-monospace | 等幅フォント（開発者向け） |

> Google Fonts のフォントは初回アクセス時にバックグラウンドで読み込まれます。`display=swap` を使用しているため、読み込み中はシステムフォントで表示され、完了次第切り替わります。

設定パネルのフォント欄の上部には**プレビュー行**があり、選択中のフォント・サイズ・行間・太字・疑似ボールドが実際のエントリと同じ見た目で即座に反映されます。

### カスタムフォント

プリセット以外のフォントも使えます。フォント欄の「カスタム」にある **＋ フォントを追加...** から、2 通りの方法で追加できます。

| 方法 | 内容 |
|---|---|
| フォント名を指定 | この端末にインストール済みのフォントを名前で指定します（例: `游明朝`）。入力すると同時にプレビューへ反映されるので、名前が正しいか確認できます。PC の Chrome では入力欄にインストール済みフォントの候補が表示されます（対応ブラウザのみ）。 |
| フォントファイルを取り込む | `.ttf` / `.otf` / `.woff` / `.woff2` ファイルを取り込みます（**3 書体まで・1 ファイル 25 MB まで**）。端末にインストールされていないフォントも使えます。 |

> - 取り込んだフォントファイルは**この端末のブラウザ内（IndexedDB）にのみ保存**され、Drive や設定バックアップには含まれません。ブラウザのサイトデータを消去すると消えますが、フォント一覧に「⚠ 再取込」ボタンが出るので、同じファイルを選び直せば復元できます。
> - 名前で指定したフォントは、別の端末にその名前のフォントが無い場合は標準フォントで表示されます。
> - 各フォントは一覧の **✕** で削除できます。使用中のフォントを削除すると既定（BIZ UDPGothic）に戻ります。

### 太字・疑似ボールド

| 設定 | 内容 |
|---|---|
| 太字で表示 | 本文を太字（ウェイト 700）で描画します。BIZ UDPGothic・M PLUS 1p / Rounded 1c・Noto Sans/Serif JP・ZEN オールド明朝・しっぽり明朝は専用の太字データを使用します。さわらび明朝・ひな明朝は太字データを持たないため簡易的な合成太字になり、その旨の注記が表示されます。 |
| 疑似ボールド | 文字の輪郭を描いて線を太らせる機能で、**なし・弱・中・強**の 4 段階から選べます。太字データを持たない書体（さわらび／ひな明朝）や細い明朝を、好みの太さに調整したいときに便利です。太字と併用もできます。 |

> 疑似ボールドは文字色と同じ色で輪郭を描くため、配色テーマを変えても自動的に追従します。

### ファイル形式

ダウンロードおよび Drive 保存時の出力形式を設定します。読込時はいずれの形式も自動認識されます。

| 設定 | 選択肢 | デフォルト |
|---|---|---|
| 改行コード | LF（Unix / macOS）/ CRLF（Windows） | LF |
| 日付フォーマット | `YYYY/MM/DD HH:MM:SS`（標準）/ `YYYY-MM-DD HH:MM:SS` / ISO 8601（`YYYY-MM-DDTHH:MM:SS+09:00`） | `YYYY/MM/DD` |
| タイムゾーン（ISO 8601 選択時のみ） | 自動（保存時のオフセット保持）/ UTC（Z）/ 固定オフセット | 自動 |

詳しい仕様は [テキストファイル形式](#テキストファイル形式) を参照してください。

> **Drive 連携時の注意**: 日付フォーマット（または ISO のタイムゾーン設定）を変更すると、次回 Drive へ保存される際に新しい形式でファイルが書き換わります。Drive 連携が設定されている状態で形式を変更すると確認ダイアログが表示され、キャンセルすると変更を取り消せます。複数端末で異なる形式を使うと毎回 Drive ファイルが書き換わるため、端末間では同じ設定にすることを推奨します（インポート側は 3 形式すべて読めるためマージ自体は壊れません）。

### 操作

| 設定 | 説明 |
|---|---|
| 新規作成（✏ ボタン）を集中執筆モードで開く | ON にすると右下の FAB が **✏** に変わる。タップで新規エントリの作成と同時に全画面モードへ入る。ヘッダの **＋新規** は常に通常モードで追加されるため、前のエントリを参照しながら書きたいときに使い分けられる |
| Drive へ自動保存 | ON（デフォルト）にすると、100文字入力ごと・入力停止10秒後・アプリ切替時・画面復帰時・オンライン復帰時・全画面終了時に自動で Drive へ保存する。Drive 未設定時は無効 |

### 設定のバックアップ

設定パネル最下部の **バックアップ** から、設定を JSON ファイルとして書き出し／読み込みできます。端末間の移行や、設定を戻したいときに使えます。

| 操作 | 内容 |
|---|---|
| ⬇ 設定を書き出す | 現在の設定を `edjiki-settings_YYYYMMDD.json` としてダウンロードします。 |
| ⬆ 設定を読み込む... | JSON ファイルを選び、確認のうえ現在の設定を上書きします。 |

**含まれるもの**: 配色テーマ・フォント・太字/疑似ボールド・フォントサイズ・行間・ファイル形式（改行コード／日付フォーマット／タイムゾーン）・各種操作設定、および Drive の接続先情報（ファイル名・保存フォルダ ID・固定ファイル ID・アーカイブフォルダ ID）。

**含まれないもの**: 日記本文、パスワード（暗号化情報）、Drive のアクセストークン。日記データそのものはこのファイルには入りません（本文の移行は `.txt` の書き出し／読み込み、または Drive をお使いください）。

> - 読み込むファイルが edjiki の設定ファイルでない場合や、より新しいバージョンで作られた場合は、メッセージを出して中断します。
> - 設定ファイル側で Drive 接続先が空（未設定）の項目は、既存の接続を壊さないようそのまま維持されます。
> - 固定ファイル ID を新たに読み込んだ場合は Drive のフルアクセス権限が必要になるため、次回の Drive 操作時に再認証が求められます。

新しい端末やデータ消去後の**ウェルカム画面**（エントリが空のとき）には「保存済みの設定から復元」リンクがあり、⚙ を開かずに設定バックアップを読み込めます。復元すると Drive の保存先が自動入力されるので、続けて「☁ Drive から読み込む」で日記を復元できます。

## Google Drive 連携

### 概要

- マイドライブ（または指定フォルダ）に単一のテキストファイルを保存・読込します。
- 複数端末で編集した場合、保存・読込時に **マージ** が行われ、双方の変更が保持されます。
- 使用するスコープは `drive.file`（このアプリが作成または開いたファイルのみにアクセス可能）です。
- Drive 接続時はヘッダのタイトルが「フォルダ名 / ファイル名」に変わります。

### Drive 自動保存

Drive 連携が設定されている状態で、以下のタイミングに自動的に Drive へ保存されます（⚙ →「Drive へ自動保存」が ON の場合）。

| タイミング | 条件 |
|---|---|
| 100文字入力するごと | Drive 認証済み・オンライン・非ロック時 |
| 入力が止まって10秒後 | 同上 |
| アプリをバックグラウンドに切り替えたとき | 同上 |
| バックグラウンドからフォアグラウンドに戻ったとき | 未保存の変更がある場合 |
| オフラインから復帰（圏内に戻った）とき | 同上 |
| 全画面モードを終了したとき | 同上 |

保存状態はヘッダのステータス表示で確認できます。

| 表示 | 意味 |
|---|---|
| **☁ Drive 接続** | Drive 自動保存が ON だが未認証 → タップして Google 認証（ページを開いた後、最初に1回だけ必要）。**未編集状態でタップすれば認証後に Drive から最新を自動取り込み**（他端末で書いた内容の反映）。書きかけがある状態でタップすると従来通り認証＆保存（pull はメニュー → Drive から読込で実行） |
| **保存中...** | Drive へ保存処理中 |
| **✓ 保存済** | 保存完了（3秒後に非表示） |
| **✕ 保存失敗** | 保存エラー → タップで再試行（トークン切れの場合は自動再認証して再試行） |

> **Drive の認証について**: アクセストークンの有効期間は約1時間です。切れた場合は「☁ Drive 接続」ボタンが再表示されるのでタップして再認証してください。保存失敗（401エラー）は自動的に再認証＆リトライが試みられます。

手動で即時保存したい場合は **⋯ → Drive に保存** または `Ctrl+Shift+D` を使います。

### 初回セットアップ

#### 1. Google Cloud Console でプロジェクトを準備する

1. [Google Cloud Console](https://console.cloud.google.com) でプロジェクトを作成（既存のプロジェクトを使っても構いません）。
2. **「API とサービス」→「ライブラリ」** で **Google Drive API** を有効化。
3. **「OAuth 同意画面」** を設定します。

4. **「認証情報」→「認証情報を作成」→「OAuth クライアント ID」** を選択。
   - アプリの種類: **「ウェブアプリケーション」**
   - 承認済みの JavaScript 生成元に以下を追加:
     ```
     https://www.ayati.com
     http://localhost:8080        （ローカル確認用）
     ```
5. 発行された **クライアント ID** をコピーしておきます。

#### 2. config.js を作成する

`config.sample.js` をコピーして `config.js` を作成し、クライアント ID を記入します。

```bash
cp config.sample.js config.js
```

```js
// config.js
window.EDJIKI_CLIENT_ID = "1234567890-xxxxxxxx.apps.googleusercontent.com";
```

#### 3. 動作確認

ローカルサーバーで `http://localhost:8080/edjiki.html` を開き、ヘッダの **⋯** メニューから「Drive に保存」を実行します。初回は Google アカウントの認証ダイアログが表示されます。

### 保存先のカスタマイズ

デフォルトはマイドライブ直下に `edjiki.txt` として保存されます。保存先は **⋯ → Drive 設定** から変更できます。また `config.js` で初期値を指定することもできます。

```js
// config.js（カスタマイズ例）
window.EDJIKI_CLIENT_ID       = "1234567890-xxxxxxxx.apps.googleusercontent.com";
window.EDJIKI_DRIVE_FILENAME  = "memo.txt";          // ファイル名を変更

window.EDJIKI_DRIVE_FILE_ID   = "1AbCdEfGhIjKlMnO"; // 既存ファイルを直接指定（後述）
```

### Drive 設定パネル

**⋯ → Drive 設定...** で開くパネルから、Drive に関するすべての設定が行えます。

| セクション | 内容 |
|---|---|
| Google Drive 連携 | メインデータの保存先フォルダを URL で指定。設定後はヘッダにフォルダ名 / ファイル名を表示 |
| アーカイブフォルダ | 年別アーカイブ（`jkYYYY.txt` / `.zip`）の保存先フォルダを設定 |
| データ管理 | ストレージ使用量確認・保持日数設定・アーカイブ実行 |
| Drive ファイル直接指定 | 他のアプリで作成した `.txt` ファイルを使う上級者向け設定（`drive` スコープに昇格） |

### Drive 操作メニュー

ヘッダの **⋯** ボタンから以下の操作が行えます。

| メニュー項目 | 動作 |
|---|---|
| ↩ 元に戻す (N) | 直前の操作を取り消す（N = 残りステップ数） |
| 💾 ダウンロード (.txt) | 現在のデータをテキストファイルとして保存 |
| 📂 ファイルから読込 | ローカルの `.txt` ファイルをインポート（現在のデータとマージ）。UTF-8 / Shift-JIS を自動判別 |
| ☁ Drive に保存 | Google Drive にアップロード。Drive 側が更新されていればマージ確認ダイアログを表示 |
| ☁ Drive から読込 | Google Drive からダウンロードしてローカルとマージ。UTF-8 / Shift-JIS を自動判別 |
| ⚙ Drive 設定... | Drive 設定パネルを開く（保存先フォルダ・アーカイブ・ファイル直接指定） |
| ❓ ヘルプ | 操作ガイドを表示 |
| ログアウト (Drive) | アクセストークンを破棄（ページを閉じると自動的に失効します） |

### マージの仕組み

複数端末で同じファイルを編集しても、保存・読込時に以下のルールで自動マージされます。

1. **エントリ ID が一致** → 同一エントリとみなし、タイムスタンプが新しい方を採用
2. **ID が一致しないが内容（日時・public/private・本文）が同じ** → 重複とみなして片方を破棄
3. **ID も内容も一致しない** → 別エントリとして追加

## アーカイブ・過去エントリ切り捨て

### 機能の目的

`localStorage` の容量（上限 約 5MB）を圧迫しないよう、一定期間より古いエントリをローカルから削除する機能です。削除したエントリは Google Drive の専用フォルダに年別ファイルとして保存されるため、**5年日記・10年日記として過去の記録をいつでも参照できます**。

アーカイブファイルは edjiki のテキスト形式なので、必要に応じて **⋯ → ファイルから読込** で現行データに取り込むことができます。

### アーカイブファイルの仕様

| ファイル名 | 内容 |
|---|---|
| `jk2024.txt` | 2024年の全エントリ（1月1日〜12月31日） |
| `jk2024.zip` | `jk2024.txt` をそのまま ZIP 圧縮したもの |
| `jk2025.txt` | 2025年の全エントリ（同上） |
| `jk2025.zip` | 同上 |
| `jk2026.txt` | 2026年の元旦〜直近のアーカイブ実行時点まで |
| `jk2026.zip` | 同上 |

**txt と zip は常にセットで保存されます。** txt はテキストエディタで直接閲覧でき、zip はファイル整理・長期保存に使えます。

#### 完全性の保証

アーカイブを複数回実行しても、年別ファイルは常に「元旦からの欠けのない記録」になります。

仕組み：実行時に Drive 上の既存 `jkY.txt` をダウンロードして今回の切り捨て分とマージしてから再アップロードします。たとえば：

- **3月に実行**（保持 60日、カットオフ = 1月中旬）→ `jk2026.txt` = 1月1日〜1月中旬
- **6月に実行**（同）→ Drive の `jk2026.txt`（1月分）＋ 今回の切り捨て分（1月中旬〜4月初旬）をマージ → `jk2026.txt` = 1月1日〜4月初旬（欠けなし）

### セットアップ

アーカイブ機能は Google Drive 設定（`config.js` に `EDJIKI_CLIENT_ID`）が必要です。

#### 1. Drive にアーカイブ専用フォルダを作成する

Google Drive で任意の場所に専用フォルダを作成します（例: `jiki_archive`）。メインデータの保存フォルダとは別にすることを推奨します。

#### 2. フォルダ ID を edjiki に設定する

⋯ → Drive 設定 →「📁 アーカイブフォルダを設定...」

1. Google Drive でアーカイブフォルダを開く
2. アドレスバーの URL をコピーしてダイアログに貼り付ける

```
https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz
                                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ この部分
```

設定後はデータ管理セクションに「✓ 設定済」と表示されます。

### アーカイブの実行

⋯ → Drive 設定 →「📦 アーカイブして切り捨て...」

#### 保持日数の設定

「保持日数」（デフォルト: 60日）以内のエントリが現行データに残り、それより古いエントリがアーカイブ対象になります。

- 今日から 60日前より古いエントリ → アーカイブ対象（Drive に保存 → ローカルから削除）
- 今日から 60日以内のエントリ → 現行データとして残る

設定画面で切り捨て対象の件数・年範囲をプレビューできます。

#### 処理の流れ

1. 確認ダイアログ（件数・年範囲・private エントリ警告などを表示）
2. Google Drive 認証（未認証の場合は OAuth フローが起動）
3. 年ごとに処理：
   - Drive の既存 `jkY.txt` をダウンロードしてマージ
   - 完全版 `jkY.txt` を Drive にアップロード（上書き）
   - `jkY.zip` を Drive にアップロード（上書き）
4. アップロード成功した年のエントリをローカルから削除

アップロードに失敗した年のエントリはローカルに残ります。

#### 注意事項

- **操作は元に戻せません。** Drive への保存を確認してからローカルデータを削除します。Drive アップロードが成功した年のみ削除されます。
- **ロック中（パスワード解除前）の private エントリはアーカイブに含まれません。** ロック中エントリはアーカイブ実行後も現行データに残ります。パスワードを解除してからアーカイブを実行することを推奨します。
- **アーカイブファイルは平文（暗号化なし）で Drive に保存されます。** private エントリを含む場合は確認ダイアログで警告が表示されます。
- アーカイブ操作には Drive の `drive.file` スコープを使用します。edjiki が作成した `jkY.txt` / `jkY.zip` のみアクセスできます（手動でアップロードした同名ファイルは認識されません）。

## データモデル

`localStorage["edjiki.data"]` に以下の JSON 形式で保存されます。

```js
{
  version: 1 | 2,              // 2 はパスワード設定済
  updatedAt: "2026-04-13T21:50:00+09:00",
  driveFileId: "1AbC..." | null,
  driveFileName: "edjiki.txt",
  driveFolderId: "1AbC..." | null,      // メインデータの保存フォルダ ID
  driveFolderName: "フォルダ名" | null, // Drive API から取得したフォルダ名（ヘッダ表示用）
  drivePinnedFileId: "1AbC..." | null,  // ファイル直接指定 ID
  driveModifiedTime: "2026-04-13T12:50:00.000Z" | null,
  archiveFolderId: "1AbC..." | null,    // アーカイブ専用フォルダ ID
  // パスワード設定時のみ存在
  cryptoSalt: "Base64...",     // PBKDF2 用 salt（16 bytes）
  cryptoVerifier: { iv, ct },  // パスワード検証用（"edjiki-verified" を暗号化）
  entries: [
    // public エントリ（暗号化なし）
    { id: "uuid", time: "2026-04-13T21:43:10+09:00", private: false, text: "本文" },
    // private エントリ（パスワード未設定）
    { id: "uuid", time: "...", private: true, text: "本文" },
    // private エントリ（パスワード設定済 → 暗号化）
    { id: "uuid", time: "...", private: true, enc: { iv: "Base64...", ct: "Base64..." } },
  ]
}
```

- `entries` は常に `time` 降順。
- `text` はフォーカスを外した時点で正規化（空行削除・末尾空白削除）。空になったエントリは自動削除。
- パスワード設定時、private エントリは `enc` フィールドに AES-GCM 暗号文として保存され `text` は含まれません。

`localStorage["edjiki.settings"]` には表示・出力設定が保存されます（日記データとは独立）。

```js
{
  theme: "auto",                 // 配色テーマ
  fontSize: 16,                  // フォントサイズ（px）
  lineHeight: 1.6,               // 行間
  fontKey: "biz-ud",             // フォント
  fontBold: false,               // 太字で表示
  fontOutline: "none",           // 疑似ボールド（"none" | "weak" | "medium" | "strong"）
  customFonts: [],               // カスタムフォント（メタのみ / バイナリは IndexedDB）
  daysToKeep: 60,                // アーカイブ保持日数
  lineEnding: "LF",              // 改行コード（"LF" | "CRLF"）
  dateFormat: "slash",           // 日付フォーマット（"slash" | "dash" | "iso"）
  isoTzMode: "stored",           // ISO 8601 出力時の TZ モード（"stored" | "utc" | "fixed"）
  isoTzFixed: "+09:00",          // 固定オフセット（isoTzMode === "fixed" のとき使用）
  autoFullscreenOnNew: false,    // FAB を集中執筆モードで開くか
  driveAutoSave: true            // Drive 自動保存
}
```

> **マイグレーション**: 旧バージョン（v0.6.x 以前）で使われていた `dateSep`（`"/"` / `"-"`）は、起動時に `dateFormat`（`"slash"` / `"dash"`）へ自動変換され、旧キーは削除されます。設定はそのまま引き継がれるので、特に意識せず新バージョンを使えます。

## 既知の制約

| 制約 | 補足 |
|---|---|
| localStorage 容量は約 5MB | アーカイブ機能で古いエントリを Drive に退避することで解消できます |
| Drive アクセストークンはタブを閉じると失効（有効期間 約1時間） | 401エラー時は自動再認証＆リトライを試みます。長時間後はヘッダの「☁ Drive 接続」をタップして再接続してください |
| `drive.file` スコープの制限 | 他のアプリが作成した同名ファイルにはアクセス不可。メインデータは「Drive ファイル直接指定」で、アーカイブは edjiki が初回作成したファイルを使い続けることで回避 |
| アーカイブの手動アップロードファイルは不認識 | `drive.file` の仕様。edjiki が初回作成した `jkY.txt` / `jkY.zip` のみ上書き更新可能 |
| `file://` では動作しない | OAuth の制限により、必ず HTTP サーバー経由で開いてください |
| パスワード紛失時の復旧不可 | private エントリは復元できません。Drive への定期保存（平文 .txt）を推奨します |
| ロック中の Drive 操作不可 | Drive に保存・読込・アーカイブを行うにはパスワード解除が必要です |
| Undo はページ再読み込みでリセット | undo スタックはメモリのみ。再読み込み後は 0 ステップから再開します |
| Shift-JIS での出力は非対応 | 出力（ダウンロード・Drive 保存）は常に UTF-8。読込時のみ自動判別します |
| 設定バックアップは日記本文・パスワードを含まない | 書き出す JSON は設定と Drive 接続先のみ。日記本文は `.txt` 書き出し / Drive、暗号化情報は移せません |
| 取り込んだフォントファイルは端末内のみ | IndexedDB に保存され、Drive・設定バックアップには含まれません。ブラウザのサイトデータ消去で消えますが、設定に情報は残り一覧に「⚠ 再取込」が出るので同じファイルで復元できます |
| フォント名の候補補完はデスクトップ Chrome のみ | カスタムフォントの名前入力での候補表示は Local Font Access API 対応環境（PC の Chrome など）限定。非対応環境では手入力になります（機能自体は利用可）。ファイル取り込みは Android を含む全環境で動作します |
| ISO 8601 形式の private 行は非標準拡張 | `2026-04-13T21:43:10+09:00* body` のオフセット末尾 `*` は edjiki 独自の拡張です（公開行は strict ISO 8601 準拠）。private を使う場合は edjiki またはその仕様に従う他のパーサで読み込んでください |
| ISO 8601 のオフセットは秒単位非対応 | `+09:00:00` のような秒精度オフセットは対応外。`±HH:MM` のみ |
